# antislop audit 009: colour pairings in the four looks, and the Phase G sheet gate (2026-10-12)

- **Mode:** after (session override). No mode question was asked.
- **Skills applied:** `building-native-ui`, `antislop` (core, ui, layoutmobile, human), `apple-design`, `design-taste-frontend` (general rules only; native mobile is outside its scope), `impeccable` (context step run once with `--target apps/customer`; colour read in its colorize and critique terms), `dataviz` (palette validator used as the contrast cross-check: it agrees that Sunrise on the light surface is 2.70:1). **`material-3` is not installed** on this machine, so Android judgements follow the Material 3 notes already in DESIGN.md.
- **Build under test:** `v2` working tree at `f5069ba2`, Expo Go SDK 57 on the Android emulator `Catera_Pixel8_API36` (1080 x 2400, 420 dpi), demo backend `CATERA_V1_DEMO=true`, data dir `.data/phase-g-a-2332`. Customer signed in as the synthetic demo customer (Nadia Putri), Dapur as the synthetic demo owner (Dapur Senja). No real account or credential was used.
- **Scope rule (owner decision D1):** this audit measures and shows. It proposes no palette direction. The owner marks the pairings first.
- **Method.** Every ratio is WCAG 2.x, computed by script (`output/native-review/phase-g/scripts/measure.cjs`) from the token values in `packages/design-tokens/src/index.ts`, then cross-checked by sampling the median colour of a pixel patch on the capture of the same pair. The full table, both columns, is `output/native-review/phase-g/audit-009/measurements.json`. Token and pixel agree within 0.05 everywhere except next to the hero's shadow, where the canvas reads slightly darker on the capture (noted in the rows).
- **How Siang and Malam were forced.** The mood is in memory, one provider per app, so no clock change was needed. Customer: the Beranda day arc (tap the sun or the moon marker); the choice then holds on every customer screen. Dapur: the Siang/Malam toggle on Hari ini. Light and dark: `adb shell cmd uimode night yes|no`, which the apps follow live ("Ikuti sistem").
- **Severity.** Text below 4.5:1 and a component boundary below 3:1 that is the only cue: **HIGH** (R-25, WCAG 1.4.11). Adjacent surfaces, measured against the kickoff's proposed separation rule of about 1.2:1 (FB2 step 7, not yet adopted): below 1.10:1 **HIGH**, 1.10 to 1.19:1 **MEDIUM**, a pass that the owner called out by eye **LOW**.

## FB7: the pale band on the hero

**Reproduced.** Recipe: clear Expo Go's image caches (`coil3_disk_cache`, `image_manager_disk_cache`, `image_cache`, `http-cache` under the app's cache folder, using `adb root`), cold start the customer app on `/pengaturan` so Beranda has not mounted, turn on airplane mode once Pengaturan has drawn, then open Beranda. The data was already read, the photo was not, so `Photo` (`packages/mobile-ui/src/PhotoRing.tsx:21`) takes `onError` and leaves its `sage` ground. `scrimSoft` (`apps/customer/src/today/Plate.tsx:478`, bottom 75%) and the 0.66 overlay darken only the lower part. Airplane mode alone, with the photo still in memory or on disk, did not reproduce it.

**Dapur blocker.** Impor's "Susun daftar" crashes with a render error twice in a row: `Transform origin z-position must be a number. Passed value: 94098883572568%.` from `MascotReading.tsx:141`, where `transformOrigin` is built as `` `${x * 100}% ${y * 100}%` `` and `readingRig.magnifierPivot.y` is `0.8094098883572568` (`packages/brand/phaseF.ts`), so the long decimal is split and read as a third value. Capture: `sheets-dapur-render-error-mascotreading.png`. The import never reaches its rows, so `impor-baris` cannot open. **Retry (owner pre-approved emulator settings):** with `animator_duration_scale`, `transition_animation_scale` and `window_animation_scale` at 0 the app reads reduced motion at launch, `MascotReading` shows its still, and "Susun daftar" no longer crashes. The demo backend then answers "Asisten impor belum aktif" and offers "Isi manual", which opens `impor-baris` with one empty row; the Dapur column above was tested that way. The crash with motion on is unchanged and still blocks the reading path for every caterer who has not turned on reduced motion. All three scales were put back to 1 afterwards. Side effect noted for the record: the console key events tried for TalkBack put Gboard into its hardware-keyboard toolbar, so the emulator was rebooted before (b) to get the full on-screen keyboard back.
