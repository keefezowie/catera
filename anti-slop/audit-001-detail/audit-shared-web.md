# Copy audit: shared packages + apps/web (read-only)

Scope: packages/mobile-ui, mobile-core (incl. push), domain, backend, api-client (user-visible strings only), supabase push/notification text (there is no supabase/functions dir; notification bodies live in SQL migrations, supabase/templates holds the two auth emails), apps/web/src.

Method: extracted every `t("id","en")` pair in apps/web/src (2,205 pairs), mobile-ui/mobile-core (110 pairs), domain/backend string literals, push migrations, email templates; then pattern-scanned for the brief's tells. Mobbin reference skimmed; it does not change any finding.

Key context: `tests/copy-scan.test.ts` already enforces a glossary on the native apps and on packages/mobile-ui, mobile-core and domain (no em dash, no "Anda", "katerer" is always "katering", no "Silakan", no "tidak dapat", "HP" not "ponsel", "data contoh" not "data sintetis", no "tanpa jeda"). It does NOT scan apps/web/src or packages/backend. Nearly every real finding below is the web app (and seed/demo text) still speaking the register the native apps retired.

Overall: shared packages are clean. Apps/web is plain and factual (little marketing fluff, no emoji, no exclamation marks, no fabricated stats), but it is stiff, bureaucratic and out of step with the glossary.

## Clean areas (no findings)
- packages/mobile-ui and mobile-core strings (110 pairs): short, verb-first, kamu register (`Coba lagi`, `Kirim ulang`, `Cek emailmu`, `Buang X?` / `Lanjut menulis`). Only nit: ExpiredLink.tsx:40/44 triad `1 jam, sekali pakai, dan di HP yang memintanya`, acceptable because it is factual.
- packages/domain `errors` map (index.ts:619-707 and EN 711-799): already humanised (`Ada yang berubah. Muat ulang, lalu coba lagi.`). Good model for the web.
- Push notification bodies (supabase/migrations/20261014130000_push_copy.sql) are already rewritten to kamu, short, with a test (tests/push-copy.test.ts) guarding them. The older `Anda` bodies in earlier migrations are superseded by that migration. Only remaining wrinkles: `Selamat menikmati!` (migration 20261014110000_push_events.sql:73) is replaced/retired by the push_events anchor swap, not shipped.
- Email templates (supabase/templates/confirmation.html, recovery.html): both use `Jika Anda tidak meminta...` and inline `ID text. EN text.` paragraphs in one block (bilingual in one string); MED-LOW, formal `Anda`, double-language body. Suggested: `Kalau bukan kamu yang minta, abaikan email ini.` and send one language per recipient locale. Not asserted by any test I found.
- apps/web/src/lib, api routes, webhooks: only log/error codes; photo-upload maps the English API errors to localised messages, so the English route messages are never shown.
- No emoji, no exclamation marks, no "Tentu!", "Jangan khawatir", "Semoga membantu", "Kami siap membantu" in scope (one `Catera siap membantu jika perlu`, customer.tsx:1866, is mild chatbot residue: LOW, rewrite `Kalau perlu, Catera ikut membantu.`).
- No fabricated stats or testimonials found.
- No not-X-but-Y constructions found in the scope.

## Consistency
- Pronoun: web mixes `Anda` (39 strings) and `-mu/kamu` (15 strings) in the same files; native + domain + push are kamu only and test-enforced.
- Business noun: web `katerer` (104) vs everywhere else `katering` (enforced) ; web `Ruang katerer` vs `Dapur`.
- Home screen: `Beranda` (nav) vs `Makanan saya` (title).
- Browse CTA: `Jelajah katering` / `Jelajah paket` / `Jelajah katerer` / `Lihat paket` / `Jelajah`.
- Order noun: pesanan / pemesanan / pembelian / langganan; EN order / booking / purchase / subscription.
- Money returned: `refund` (web, 18 strings, "Proses refund", "Jumlah refund (Rp)") vs `pengembalian dana` (web 6, push, domain errors).
- Failure phrasing: `Belum berhasil...` (20), `Gagal...` (12), `Tidak dapat...` (10), `Coba lagi` (shared). Native glossary treats the generic failure as last resort.
- Demo label: `data sintetis` (web, backend) vs `data contoh` (glossary).
- Language: contents.ts/offer-editor.ts and the two auth emails put ID and EN in one string.
- Currency in form labels: `(Rp)` / `(IDR)` pairs are consistent; `Rp 100.000` placeholder fine.

## Verdict
The shared native packages, the domain error map and the push copy already sound like a short, casual kamu-voiced Indonesian app. Apps/web does not: it reads as a careful translation of an operations console, full of `Anda`, `katerer`, `ditinjau`, `telah`, `dapat`, `Silakan` and `belum berhasil`, with em dashes as separators and placeholders and one English-only tagline in the page title and PWA name. The fixes are mechanical (a glossary pass over apps/web/src, extending tests/copy-scan.test.ts to include it), not a tone rewrite, because the web copy is factual and avoids hype, emoji, and invented claims. Highest value: the title/manifest string (#1), the em dash sweep (#2-#6), and the Anda->kamu / katerer->katering pass (#7, #8, #12), which would also remove the web/native divergence. Changing #7, #10, #16 requires updating the e2e and unit tests listed in the last column.
