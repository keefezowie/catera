## Data and security

`20260916061905_seller_experience.sql` adds private `v1.payout_destinations` and `v1.account_requests`, tenant-scoped RPC wrappers, and the private 8 MiB staging bucket. Direct authenticated table access is revoked. Ordinary bank responses and audit records contain masked details; only explicit admin detail reads and service-side payout resolution expose full account data. Account-help text and message bodies are excluded from audit entries.

Bank review requires verified routing and provider recipient identity. Individual names include provider-required given name and surname; single-name identities require an accepted provider format before approval. Business names use the provider's separate business field. Approval does **not** switch on dispatch or establish provider readiness. Existing environment-configured recipients remain the fallback until an approved destination exists. Recipient selection and capture use the same tenant advisory lock as approval; retries retain the captured request.

The staging bucket has no authenticated write/read policies. Object-scoped signed tokens permit upload, and completion uses server credentials after checking ownership. The migration removes the old `Catera owners upload food photos` INSERT policy, preventing unvalidated direct public uploads. The compatibility `/api/uploads` endpoint also validates bytes before server-side publication. Cleanup runs through the existing protected jobs endpoint, deleting up to 100 staged objects older than two hours per run; cleanup failure does not block financial jobs. Image decoding is limited to 40 million pixels as well as 8 MiB compressed bytes.
