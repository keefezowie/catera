# Saved Packages and Swipe Discovery

Approved extension of Catera V1, October 2, 2026. The user selected Saved first, deferred a cart, chose mobile swipe as the default with a visible list alternative, and required login before saving. Web acceptance precedes native release. PRODUCT.md and DESIGN.md remain the authority for purchasing and the established visual system.

## THESIS

Help a customer find one suitable catering package, keep it for later, and return to the same choice after inspecting details, comparing, or signing in. Saved expresses interest; it does not reserve a delivery cycle, capacity, price, or payment.

## OWN WORLD

This is an extension of the incumbent food-led Catera marketplace. Preserve Forest, Sunrise, cream surfaces, Jakarta typography, existing icons, approved Catera artwork, Indonesian-first copy, and actual catalog photographs. Introduce no palette, font, image collection, naming exercise, or replacement identity. Existing current package data is authoritative; an unavailable saved item retains only its identity snapshot.

## STORY

Discover → swipe one package per deliberate gesture or select List → Save or compare → inspect package → return to the same filtered card → configure the delivery cycle in the existing checkout. A guest Save carries one expiring intent through login. The private Saved page supports current offers and clearly unavailable items, including removal and empty/error recovery. `/home` remains the customer's meal agenda.

## FIRST VIEWPORT

On a fitting mobile viewport, the marketplace immediately shows its area/search controls, filters and visible Swipe/List choice above one food photograph and package essentials. Show caterer, package name, per-meal price, cycle/meal information, delivery coverage, and explicit Save, Compare, and View package actions. Keep navigation and the comparison tray clear of those actions. Next/previous buttons and the position counter make the mechanism discoverable without relying on touch. Desktop retains the incumbent landing page and list.

## FORM

Operate inside the existing discovery surface. The signature interaction is a vertical gesture that moves at most one package; short, cancelled, horizontal, and boundary gestures do not skip packages. No automatic advance or swipe-to-buy/save. Filter changes start at the first matching item; returning from details/comparison/login retains the selected card when still present. A remembered view preference is overridden by an explicit URL. Reduced motion uses immediate transitions. Small heights or enlarged text fall back to the full list so essential actions remain accessible. Native uses the same contract with platform controls and an unnested virtualized pager. Native keyboard and large-text behavior must be confirmed on real OS surfaces before release.
